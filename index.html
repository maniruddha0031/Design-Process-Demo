Section 2 · Claude Introduction

What is Claude?

Claude is an AI assistant that can read, write, and reason about code directly — inside your editor, across your whole project.

💡 Code generation 📖 Code explanation 🐞 Debugging ♻️ Refactoring 🎨 UI creation 📝 Documentation 🔍 Understanding existing code 📂 Working across multiple files ✅ Testing 🤖 Agentic development

Section 5 · Effort / Reasoning

Match Effort to the Task

Low / Fast

Small, simple changes

e.g. "Change this button's color to blue."

Medium

Normal development tasks

e.g. "Add a new feature to the dashboard."

High

Complex / multi-file work

e.g. "Debug a complex issue across multiple files."

✓ Advantages of higher effort

  • Better reasoning for complex tasks
  • Better analysis
  • Useful for debugging
  • Useful for architecture decisions

✗ Disadvantages

  • May take longer
  • Can consume more resources/tokens
  • Overkill for simple tasks
Key message: do not always use the highest effort — match effort to task complexity.
Speaker Notes

Effort ya reasoning level ka matlab hai Claude kitna "soch" ke jawab de raha hai. Chhote kaam ke liye Low use karo — fast aur efficient. Complex debugging ya architecture ke liye High use karo. Hamesha High use karna zaroori nahi, aur kabhi kabhi waste bhi hota hai.

Section 6 · Project Structure

Why this matters

  • Cleaner context for Claude
  • Easier development
  • Easier Git management
  • Easier GitHub upload
  • Easier deployment
  • Easier collaboration & maintenance
  • Prevents mixing unrelated projects
Speaker Notes

Yeh rule bahut important hai — ek project, ek folder. Agar hum multiple projects ek hi folder mein rakhenge, toh Claude ka context confuse ho jaata hai aur GitHub upload/deployment bhi mushkil ho jaata hai.

Section 6 · Project Structure

Structure Comparison

✗ Bad

One folder ├── Project A files ├── Project B files ├── Project C files └── random files...

✓ Good

Project A/ → its own folder → its own Git repository Project B/ → its own folder → its own Git repository
Speaker Notes

Left side dekhiye — sab kuch ek hi jagah mixed hai, isse GitHub upload aur deployment dono confusing ho jaate hain. Right side ka approach follow karo: har project apna folder, apna repository.

Section 7 · Git-Friendly Design

Why this structure works

Simple UI ya prototype projects ke liye plain HTML/CSS/JS best hai — koi build step nahi, directly browser mein chalta hai, aur GitHub Pages par bina kisi extra setup ke deploy ho jaata hai.

Section 10 · Agentic AI

Advantages & Disadvantages

✓ Advantages

  • Faster development
  • Multi-file changes
  • Project-wide understanding
  • Strong debugging support
  • Repetitive task automation
  • Faster prototyping
  • Can perform multiple development steps at once

✗ Disadvantages

  • Can make incorrect changes
  • Can introduce bugs
  • Can modify unrelated files
  • Can misunderstand requirements
  • Can execute commands
  • Security / privacy concerns
  • Can create code developers don't fully understand
  • Blind acceptance can cause problems
"AI can accelerate development, but humans must review the result."
Speaker Notes

Agentic AI ka biggest advantage ye hai ki humein har chhota step manually batana zaroori nahi hota. Lekin isi wajah se risk bhi badhta hai, kyunki AI multiple files ya commands modify kar sakta hai. Isliye Git aur review bahut important hai — agla slide yehi dikhata hai.

Section 14 · Public vs. Private

Choosing Repository Visibility

🌐 Public Repository

Anyone can potentially see the source code.

Use for:

  • Portfolio projects
  • Open-source work
  • Public demos
  • Non-confidential prototypes

🔒 Private Repository

Only authorized users can access it.

Use for:

  • Internal projects
  • Company projects
  • Client-related code
  • Confidential / sensitive work
⚠ Never make company, client, or confidential code Public unless explicitly authorized.
Speaker Notes

Yeh decision casually mat lo. Agar code company ya client se related hai, toh default Private rakho. Public sirf portfolio ya open-source jaise non-confidential cases ke liye hai.

  • Tokens
  • Database credentials
  • Client secrets
  • Private certificates
  • Production credentials

✗ Bad

a secure secret manager

Section 27 · Do / Don't

Quick Reference

✓ Do

  • One project = one folder
  • Prefer clean HTML/CSS/JS for simple prototypes
  • Use Git from the beginning
  • Review AI changes
  • Review the Git diff
  • Test before deployment
  • Keep repository structure clean
  • Use meaningful commits
  • Keep secrets out of GitHub
  • Use private repos for confidential projects
  • Give minimum required permissions

✗ Don't

  • Mix multiple projects together
  • Blindly trust Agentic AI
  • Upload secrets
  • Make confidential code Public
  • Push untested code
  • Give Admin access unnecessarily
  • Ignore repository visibility settings
  • Assume a private repo means a private website

Section 28 · Common Mistakes

Common Mistakes to Avoid

  • One repository for multiple unrelated projects
